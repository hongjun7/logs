> **The idea in one minute.** `owl:sameAs` says two names denote the same thing. Explicitly substituting every equivalent name into every fact can create a combinatorial explosion. A reasoner can instead store one representative per equivalence class, provided it updates rules and expands query answers with the correct semantics.

**Reading path.** Start with the three-name example. Continue to the invariants and fixpoint argument. The SPARQL section explains why a compact fact store is not automatically a correct query engine. The discussion concerns rule materialization with equality; it is not a claim that arbitrary OWL reasoning reduces to union–find.

## 1. Names, individuals, and equivalence classes

An RDF graph is a set of triples $$(s,p,o)$$. Under an equality-aware interpretation, different names may denote one individual. Write $$a\sim b$$ for the equivalence relation generated by equality facts. Reflexivity, symmetry, and transitivity give an equivalence class

$$
[a]=\{b:b\sim a\}.
$$

Choose a representative map $$\rho$$ satisfying

$$
a\sim b\iff\rho(a)=\rho(b),\qquad\rho(\rho(a))=\rho(a).
$$

The second equation is idempotence: normalizing twice does not change a normalized term. Extend $$\rho$$ componentwise to triples and to constants in rules. For example, if `:US`, `:USA`, and `:America` are equal, choose `:US` and store `(:person, :livesIn, :US)` once.

`owl:sameAs` is stronger than a similarity link. It permits replacing equal individuals in statements. Whether replacing a predicate name is part of the intended reasoning regime depends on the RDF-based equality rules being used. The scope here follows the rule treatment in the original rewriting paper and the OWL 2 RL/RDF rules, rather than silently applying every RDF-term operation as if it respected semantic equality. [OWL 2 profiles](https://www.w3.org/TR/owl2-profiles/).

## 2. Where the explosion comes from

A class containing $$k$$ names has $$k^2$$ ordered equality pairs, including self-pairs. For a triple whose subject, predicate, and object classes have sizes $$k_s,k_p,k_o$$, explicit substitution can produce up to

$$
k_s k_p k_o
$$

distinct syntactic triples. This is a bound on expanded facts, not a universal count of rule firings. The number of derivations also depends on the rule set, duplicate suppression, and execution schedule.

Consider `:alice` and `:a` in one class, and the three country names above in another. One normalized `livesIn` fact represents $$2\cdot1\cdot3=6$$ syntactic triples. A quotient store holds the normalized triple plus the class membership map. It has compressed the representation, while the externally visible name-level answers may still contain six combinations.

With a union–find structure, $$m$$ union/find operations on $$n$$ items have amortized $$O(m\alpha(n))$$ cost using standard path compression and union by rank. This only bounds the disjoint-set operations. Rewriting affected facts, updating indexes, and rerunning rules can dominate total reasoning time.

## 3. Why preprocessing is insufficient

Suppose a rule can itself infer equality:

```text
sameAs(x, :USA) :- presidentOf(:person, x).
leader(x)      :- presidentOf(x, :USA).
```

A fact `presidentOf(:person, :US)` may infer `sameAs(:US, :USA)`. If `:US` becomes the representative, the constant `:USA` in the second rule must also become `:US`, or rule matching must normalize constants dynamically. Rewriting facts alone would make an applicable rule disappear from the execution engine's view.

New equalities may expose new matches, which may expose more equalities. Thus equality normalization and materialization have to proceed together toward closure. A one-time preprocessing step is sound only when all required equivalences are already known and will never change under the program.

## 4. The central invariants

Let $$E$$ be input facts and $$P$$ a finite, safe, function-free positive rule program with the chosen equality rules. Its ordinary materialization is a least fixpoint. A compact algorithm maintains a normalized fact set $$T$$ and a representative map $$\rho$$.

For a triple set, define its name-level expansion by

$$
\operatorname{expand}_\rho(T)
=\{(s,p,o): (\rho(s),\rho(p),\rho(o))\in T\}.
$$

Equality facts and inconsistency handling need the chosen engine's conventions as well; this expression describes the substitution component of the representation. Correctness requires that the compact representation recover the same relevant consequences as explicit equality materialization.

Three operational requirements follow:

1. **Normalize facts.** Every live fact must eventually use current representatives. A class merge invalidates facts containing the old representative.
2. **Normalize rules.** Rule constants and rule-matching indexes must agree with the current map. Changed rules must be reconsidered against existing facts.
3. **Do not lose work.** A new fact or a new equality must eventually trigger all rule instances that become applicable because of it.

In a finite domain, positive materialization can add only finitely many ground facts, and equality merges can reduce the number of classes at most $$n-1$$ times. This supplies a termination argument for a fair implementation with finite rule processing. It does not prove a particular concurrent implementation is race-free.

For soundness, show each normalized derivation expands to consequences of the original rules and known equalities. For completeness, take an explicit derivation and induct on its length: normalized premises must be represented, rule constants must be normalized, and fair reevaluation must eventually produce the normalized conclusion. These are the obligations behind the rewriting optimization.

## 5. Parallel materialization

The Motik et al. algorithm integrates fact processing with queues for changed resources and rewritten rules. It may mark outdated facts rather than immediately remove them; matching must then ignore invalid versions. A merge needs coordinated updates to the equality structure, occurrence indexes, and pending work. The paper's synchronization choices are implementation details of that algorithm, not a promise that all equality reasoners are lock-free. [Handling owl:sameAs via rewriting](https://ojs.aaai.org/index.php/AAAI/article/view/9187).

An understandable implementation model is:

```text
take pending fact or equality update
normalize it with the current representative map
if it merges classes:
    enqueue affected facts and affected rule constants
otherwise:
    apply matching rules and enqueue new facts
repeat until all work, including rule reindexing, is complete
```

A queue being temporarily empty is not enough for termination when another worker can still publish derived work. The termination detector has to account for active workers and delayed updates. Likewise, deleting an equality later is not an ordinary union operation: a previously merged class may need to split, often requiring a different maintenance strategy or recomputation.

## 6. SPARQL set and bag semantics

A compressed graph must preserve query semantics, including duplicate solution mappings. Suppose the subject class contains two names and an object class contains three names. The normalized store has one `livesIn` fact.

```sparql
PREFIX : <urn:example:>
SELECT ?s WHERE { ?s :livesIn ?country }
```

On the expanded graph, each subject name appears three times, once for each object name. The answer multiset has size six. Simply projecting the normalized match and expanding the subject yields only two rows. The lost factor comes from the projected-away variable.

For a basic pattern whose variables independently choose members of represented classes, a normalized binding $$\nu$$ has an expansion multiplicity

$$
\prod_{x\in\operatorname{vars}(Q)}\vert [\nu(x)]\vert .
$$

This is a useful special-case count, not a general SPARQL optimizer rule. Repeated variables, fixed constants, filters, joins, and already expanded variables constrain the independent choices. `SELECT DISTINCT ?s` removes output duplicates and would return only the two subject names.

Builtins expose a second problem:

```sparql
PREFIX : <urn:example:>
SELECT ?label WHERE {
  ?s :livesIn :US .
  BIND(STR(?s) AS ?label)
}
```

Equal individuals can have different IRI strings. `STR(:alice)` and `STR(:a)` are different lexical results. Expand the relevant names **before** evaluating operations that inspect their syntax. Do not normalize lexical strings afterward and expect to recover the lost distinctions. [SPARQL 1.1 query semantics](https://www.w3.org/TR/sparql11-query/).

## 7. Inconsistency and practical use

If equality closure identifies two resources explicitly asserted different, the theory may be inconsistent. An engine may report a contradiction rather than materialize every consequence of classical explosion; query behavior on inconsistent data must be documented separately. A compact equality map does not choose an inconsistency semantics for us.

Use rewriting when equal-name substitution materially enlarges closure and the engine preserves query behavior. Evaluate normalized facts, expanded answer counts, wall time, memory, and update cost separately. Include filters and projections in the query suite. Historical improvements in one paper do not imply an invariant speedup on a new graph with few equalities.

## 8. A least-fixpoint view of positive rules

For a finite ground universe, write the inflationary immediate-consequence operator as

$$
T_P(S)=E\cup S\cup\{h\sigma:
(h\leftarrow b_1,\ldots,b_m)\in P,
\;b_i\sigma\in S\text{ for all }i\}.
$$

Here $$\sigma$$ is a substitution of variables by domain terms. Safety and a function-free finite domain make the ground universe finite. Positivity gives monotonicity: if $$S\subseteq S'$$, every rule instance applicable in $$S$$ is also applicable in $$S'$$. Starting from $$E$$, the ascending chain $$S_{k+1}=T_P(S_k)$$ stabilizes at the least fixpoint containing $$E$$.

Rewriting stores a quotient of this process. The representative map changes when new equality is derived; therefore one cannot assume a single fixed normalized program from the start. The induction argument must account for class merges and newly applicable rule instances. If a merge normalizes two previously distinct constants to the same representative, a join that once failed may now succeed even without a newly inserted ordinary fact. This is why rule and index reevaluation is part of correctness.

A semi-naive engine reduces repeated derivations by joining with newly added facts. Under equality rewriting, “new work” includes changed equivalence classes and rewritten rule constants, not just ordinary fact insertion. Reusing an unchanged delta mechanism without representing those changes can miss consequences.

## 9. Lexical identity and semantic equality are distinct

Consider two equal names `:alice` and `:a`. At the RDF-term level they are still different IRIs. SPARQL operations that inspect lexical identity do not simply become equal because an OWL rule asserts that they denote the same individual.

```sparql
PREFIX : <urn:example:>
SELECT ?x ?y WHERE {
  ?x :relatedTo ?y .
  FILTER(!sameTerm(?x, ?y))
}
```

If a normalized self-related representative expands to both names, some expanded pairs have equal terms and some do not. Filtering the one representative pair before expansion loses the latter. An execution engine can postpone the filter, expand exactly the relevant variables, or implement an equivalent symbolic calculation. It cannot pretend that syntax-sensitive functions factor through the quotient.

For repeated variables, assignments must remain consistent. A pattern `?x :relatedTo ?x` chooses one name for `?x`, not one subject name and a separate object name. If the normalized class has two members and all required expanded self-triples exist, that binding expands to two assignments, not four. Count distinct variables and enforce their equality constraints before applying any independent-choice product.

This principle also applies to lexical ordering, string conversion, and any extension function that inspects the spelling of a term. [SPARQL's function definitions](https://www.w3.org/TR/sparql11-query/) are the authority for those operations; the equality reasoner's compression is an internal representation choice.

## 10. Deletion demonstrates why provenance matters

Suppose the only asserted equality links are $$a=b$$ and $$b=c$$. Their closure puts all three names in one class. Deleting $$a=b$$ from the assertions should leave $$a$$ separate from the class $$\{b,c\}$$, unless another rule derivation still proves its equality.

A union–find structure cannot undo that merge by deleting one stored edge. Derived equalities in the previous closure also cannot be treated as independent surviving assertions. Correct deletion needs dependencies/provenance, a truth-maintenance strategy, or recomputation of the affected closure. The choice is a lifecycle and workload tradeoff, not a minor extension of insertion-only union.

For testing, maintain a small explicit equality/materialization oracle over a finite universe. Compare expanded triples and full query multisets after each insertion or deletion. Include class merges that enable a constant-bearing rule, projections that hide a multiplicity factor, and lexical filters that disagree on equal names. A fact-count comparison alone can miss all three classes of defect.
